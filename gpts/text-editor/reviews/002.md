## Output container

Version 002 states the output container explicitly: plain Markdown, two language blocks separated by a horizontal rule, no code fence, quotation, or other wrapper around either block, and no request for interface features such as writing blocks.

A draft asked the model for native editable writing blocks, one per language, so each could be edited and copied separately. It was withdrawn on 2026-09-20 after reading [Working with writing blocks and code blocks in ChatGPT](https://help.openai.com/en/articles/20001246), fetched through Firecrawl because the help center refuses direct requests:

- ChatGPT places a draft in a writing block on its own judgement, "when ChatGPT creates text that you are likely to revise or reuse". Nothing in the article gives a GPT's instructions control over that choice, and nothing promises two blocks in one response.
- The formatting a writing block supports is bold, italic, headings, links, bulleted and numbered lists, and checklists. Tables are absent, so a Russian table would fall back to ordinary text in exactly the case the draft was written for.
- Availability "depends on the type of block, your device, your plan, workspace settings, and whether the feature is enabled for your account".

Plain Markdown is what every renderer already handles. A second opinion from Codex on 2026-09-20 agreed and pointed out that a blank line alone lets two lists render as one, which is why the blocks are separated by a horizontal rule. A wrapper can only lose: a code fence shows headings as raw text and breaks when the source contains its own fence, and a writing block drops tables. If the interface places a response in a writing block on its own, record that as an interface observation, not as a prompt failure.

The same fetch of [Creating and editing GPTs](https://help.openai.com/en/articles/8554397-creating-a-gpt), updated four days before this review, says OpenAI plans to retire custom GPTs in favour of Plugins, with Enterprise retirement planned for 2026-12-11 and other plans expected to follow. The article states no character limit for the Instructions field. Its advice for instructions, explicit step structure, positive instructions over prohibitions, brief examples of acceptable and unacceptable output, headings and lists, is what this version follows.
